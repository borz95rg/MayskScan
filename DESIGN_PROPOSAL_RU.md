# Вариант дизайна Maysk Scan

## Направление

Сохранить референс: тёмный фон, тонкие неоновые контуры, яркие синие действия и цветовые акценты по типу документа. Для Word оставить синий, Excel — зелёный, PowerPoint — оранжевый. Не переносить в интерфейс элементы настольного Office, если у них нет рабочего действия.

## Что уже совпадает с референсом

- Тёмная палитра и цвет редактора по формату.
- Лента вкладок и компактные команды форматирования.
- Нижние ярлыки страниц/листов/слайдов и переключение стрелками.
- Плавающая кнопка локального AI-помощника.
- Экран локального AI теперь использует ту же тёмную палитру, неоновые карточки и акцентные кнопки; поле запроса корректно работает с экранной клавиатурой.
- В редакторе кнопка сохранения получила облачную иконку, статус Excel показывает подсказку для сводки выделения вместо счётчика слов, а старые форматы `.doc/.xls/.ppt` явно помечаются как доступные только для просмотра.
- Экран списка файлов, фильтры форматов, меню файла и создание документа.
- GitHub Actions собирает APK, публикует артефакты, а при наличии секретов подписи и публикации выпускает обновление.

## Мой вариант завершённого интерфейса

### Библиотека документов

Оставить референсную структуру, но сделать её спокойнее и понятнее: заголовок «Документы», строка поиска, компактные фильтры Word / Excel / PowerPoint / PDF, затем список карточек. На карточке показывать тип, имя, дату изменения и место хранения. «Недавние» и «Избранное» вынести в переключатели над списком; создание — в одну заметную кнопку «+». Если документов ещё нет, вместо пустого экрана показать «Открыть файл» и «Создать документ».

### Редактор

Верхняя строка: назад, сокращённое имя файла, явный статус сохранения и меню. Под ней — горизонтальные вкладки и одна прокручиваемая лента команд. Для Word оставить жирный, курсив, подчёркивание, отмену и повтор; для Excel — эти же поддерживаемые действия и сводку выделенных чисел; для PowerPoint — форматирование текста и запуск показа. Неактивные для текущего типа команды скрывать.

Документ должен оставаться самым большим элементом экрана. Нижняя панель показывает текущую страницу, лист или слайд, стрелки навигации и сохранение. На PowerPoint оставить номера слайдов, пока движок не предоставляет надёжные миниатюры. Свайп страниц не использовать, чтобы не конфликтовать с выделением и прокруткой таблиц.

### AI и история

AI-панель открывать как компактный нижний лист с действиями: перефразировать, сократить, расширить, перевести, проверить. Для выделенного фрагмента применять его как контекст; если выделения нет — анализировать документ. Ответ пока показывать отдельно, с кнопкой копирования и короткой подсказкой, что вставка в редактор выполняется вручную.

Историю версий оформить списком с датой и временем сохранения, размером и явным действием «Восстановить». Сравнение версий не показывать, пока оно не реализовано.

## Приоритеты до публикации

1. На реальном телефоне проверить отступы, клавиатуру, выделение, прокрутку таблиц, сохранение и повторное открытие.
2. Согласовать редактор, главный экран и остальные вспомогательные экраны по размерам карточек, скруглениям, акцентам и состояниям нажатия; избегать чрезмерного свечения, чтобы текст оставался читаемым.
3. Явно показывать только доступные движку команды; AI-результаты и версии обозначать как отдельные сценарии.
4. Проверить установку обоих APK из GitHub Actions. 64-битная сборка нужна для локального LiteRT-LM; 32-битная сохраняет офисные функции без локальной генеративной модели.

## GitHub-запуск

Workflow `.github/workflows/build.yml` запускается при push в `main`/`master`, вручную через Actions и теперь при Pull Request в эти ветки. Для PR собираются APK-артефакты, публикация релиза и запись обновления пропускаются. Подписание и публикация релиза по push требуют настроенных GitHub Secrets, описанных в README.
