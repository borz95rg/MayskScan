# MayskScan — план офлайн-офиса и умного помощника

## Уже было в проекте до этой доработки

- Сканирование, OCR, перевод с загружаемыми языковыми моделями, PDF-инструменты, QR, голосовой ввод, история и резервные копии.
- Чтение DOCX и XLSX для конвертации/извлечения текста.
- Создание DOCX/XLSX/PPTX при конвертации; PPTX-экспорт ранее был ориентирован на изображения страниц.
- Получение PDF и изображений через Android «Открыть с помощью».

## Реализовано в текущей рабочей версии проекта

1. Единый экран «Документы» с выбором локальных файлов через Android Storage Access Framework.
2. `OpenActivity` принимает распространённые DOCX, XLSX, PPTX, TXT, CSV и PDF через системные действия Android; неизвестные форматы передаются подходящему внешнему приложению.
3. Для DOCX/PPTX/XLSX добавлен консервативный OOXML-редактор: он меняет существующие текстовые узлы прямо внутри исходного ZIP-пакета, не пересоздавая документ из обычного текста.
4. DOCX: редактируются текстовые фрагменты документа, колонтитулов и сносок. Существующие свойства шрифта, абзацев, таблиц, изображений и прочие части пакета сохраняются.
5. PPTX: редактируются существующие текстовые фрагменты слайдов; макеты, тема, изображения, диаграммы, переходы и анимации не пересобираются.
6. XLSX: редактируются текстовые фрагменты shared strings, inline-строки и простые числовые значения; формульные ячейки пропускаются, чтобы не повредить формулы. Стили, листы, диаграммы и остальные части пакета остаются на месте.
7. Большие документы редактируются постранично небольшими группами текстовых фрагментов, чтобы не создавать тысячи полей одновременно.
8. Перед записью поверх исходника создаётся локальная резервная копия. Если Android не даёт права записи, предлагается сохранить отдельную копию через системное окно.
9. TXT/CSV/MD/HTML/RTF продолжают редактироваться как текстовые файлы.
10. Локальный помощник сохраняет базовые инструменты: краткое содержание, ключевые пункты и эвристическую классификацию.

## Ограничения текущего офисного редактора

- Это формат-сохраняющее редактирование существующих текстовых фрагментов, а не полноценный визуальный аналог Microsoft Word/Excel/PowerPoint.
- Сейчас нельзя свободно добавлять новые таблицы, страницы, листы, слайды, изображения, диаграммы, формулы, анимации и менять произвольные стили через визуальные панели.
- В XLSX изменение элемента общего shared-string может затронуть несколько ячеек, которые ссылаются на один и тот же текстовый элемент; редактор показывает ссылки на такие ячейки.
- Старые бинарные DOC/XLS/PPT, ODT/ODS/ODP, Apple Pages/Numbers/Keynote и другие специальные форматы передаются внешнему приложению, если оно установлено. PDF обрабатывается существующим PDF-модулем.
- Перезапись исходника возможна только при наличии выданного Android права записи. В противном случае доступно сохранение копии.
- Полная Android-сборка и тестирование на физическом устройстве пока не выполнены в этой среде: отсутствуют Gradle и Android SDK.

## Следующие этапы

### Этап 3 — полноценный визуальный офисный движок

- Оценить совместимые с Android движки по качеству рендеринга, редактированию DOCX/XLSX/PPTX, размеру APK, ABI ARM64/ARMv7, лицензии и возможности офлайн-работы.
- Главный кандидат для проверки — OpenDocument.core (MPL-2.0): Android AAR рендерит документы локально и умеет редактировать/сохранять DOCX, XLSX, PPTX и ODF; старые DOC/XLS/PPT открывает с ограничениями.
- У OpenDocument.core Android AAR минимальный Android API 26, тогда как MayskScan сейчас поддерживает API 23. AAR включает нативные библиотеки для нескольких ABI; в документации указаны примерно 60–72 МБ библиотек на ABI. До интеграции нужно принять компромисс по минимальной версии Android и размеру APK.
- Альтернативы (например, Kern под AGPL-3.0) рассматривать только после проверки зрелости, лицензии и того, насколько хорошо сохраняются сложные документы.
- Не использовать упрощённую пересборку файлов из текста как замену полноценному редактору.
- Цель Word: форматирование текста, таблицы, изображения, колонтитулы, поиск/замена и комментарии.
- Цель Excel: формулы, стили ячеек, листы, фильтры, сортировка, объединения и диаграммы.
- Цель PowerPoint: визуальный редактор слайдов, текст, фигуры, изображения, диаграммы, заметки и переходы.
- Сохранение в исходный файл только после резервного копирования и при наличии права SAF; иначе — отдельная копия.

### Этап 4 — настоящая локальная нейросеть

- Использовать актуальный LiteRT-LM Kotlin API для локального запуска открытой модели; не начинать новый модуль на MediaPipe LLM Inference, поскольку Google перевёл его в режим поддержки существующего API и рекомендует миграцию на LiteRT-LM.
- Текущий проект использует Kotlin 1.9.24; новые версии LiteRT-LM могут требовать более свежие Kotlin metadata. Проверить совместимую версию SDK и спланировать обновление Kotlin/AGP до подключения runtime.
- Модель не включать в APK. Пользователь скачивает её отдельно по Wi-Fi, видит размер и требования к RAM/свободному месту, может приостановить, удалить или заменить модель.
- Сначала предложить компактную модель для устройств с достаточной памятью; более крупные варианты показывать только на совместимых устройствах.
- Реализовать RAG-подобную работу с документом: извлечение текста, разбиение на фрагменты, поиск релевантных фрагментов и ответы со ссылкой на страницу/лист/слайд/абзац.
- Функции: вопрос-ответ по документу, краткое содержание, извлечение дат/сумм/реквизитов, объяснение сложных пунктов, переписывание и проверка текста.
- Все запросы по умолчанию выполнять на устройстве; не загружать документы в облако. Явно показывать, когда модель не установлена или устройство не поддерживается.

### Этап 5 — библиотека документов

- Индексация текста и метаданных, поиск по содержимому, теги и умные папки.
- Автоматические названия и категории с подтверждением пользователя.
- История версий, автосохранение черновиков, восстановление после сбоя, поиск дубликатов и сравнение версий.

## Проверки, выполненные для текущей версии

- `OoxmlPreservingEditor.kt` скомпилирован локальным Kotlin-компилятором.
- На тестовых DOCX, XLSX и PPTX проверено чтение текстовых фрагментов, изменение узлов и запись нового ZIP-пакета.
- Проверено, что неизменённые части тестовых Office-пакетов остаются в архиве.
- XML `AndroidManifest.xml` ранее проверялся на корректность.
- Полную Android-сборку и UI-тесты выполнить нельзя: в среде нет установленного Gradle/Gradle Wrapper JAR и Android SDK. Перед выпуском APK необходима сборка в Android Studio или GitHub Actions и тестирование на реальном устройстве.
